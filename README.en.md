A one-hand **14-key hall-effect (magnetic switch)** keyboard based on an Arduino Leonardo
(ATmega32u4). Firmware and host tool are both written by me. It supports **rapid trigger (RT)**,
**upper/lower dead zones**, **calibration** and an **EC11 encoder**; parameters and mappings live
in EEPROM and are configured through
[KeyboardOG](https://github.com/LGGZi/KeyBoard-OG-key-binding-tool):

```
host ──(HID Report ID 4, 8-byte commands)──> firmware
     <─(ACK / FIN / query data / device info)─
```

> **No keys are bound by default** — write your mappings with the host tool first.
> **Calibrate once before first use** (hold the knob button, or "Calibrate all" in the host),
> otherwise the dead zones are computed from the wrong travel range.

## Features

### Rapid trigger + dead zones

- **Dead zones are checked first**: if the reading is in the upper dead zone (near released) or
  the lower dead zone (bottomed out), that wins; RT tracking only runs inside the normal range.
- Inside a dead zone the opposite threshold is pinned to "boundary ± travel", so leaving the
  dead zone requires pressing `rt_active` deeper again — a 1–2 count wobble can no longer
  produce a **double click**.
- Parameters (stored as per-mille in EEPROM, converted to ADC counts at load):

  | Parameter | Meaning | Range |
  |---|---|---|
  | `rt_active` | RT press distance | 10..500 ‰ |
  | `rt_deactive` | RT release distance | 10..500 ‰ |
  | `high_deadzone` | force release near the top | 0..200 ‰ (0 = off) |
  | `low_deadzone` | force press at the bottom | 0..200 ‰ (0 = off) |

  Conversion: `distance = (bt_maximum - bt_minimum) × parameter / 1000`, i.e. the whole travel
  is divided into 1000 units.

### Calibration

- Hold the knob button for more than 10 loops and release to calibrate everything;
- the host can also calibrate a single key or all keys and shows progress per key;
- the extremes (`MAX_VALUE` / `MIN_VALUE`, raw ADC 0..1023) are stored in EEPROM, so calibration
  survives a power cycle.

### Key mappings

- Up to **12 bindings per key**, applied in order, mixing keyboard / mouse / gamepad / media
  keys; modifiers are translated to the HID modifier byte.
- Mappings are level-triggered: a held key keeps reporting.

### EC11 encoder

- Quadrature decoding (A/B on D2/D3, internal pull-ups), four quarter-steps per detent.
- Emulated as media-key pulses by default: counter-clockwise → volume up, clockwise → volume down.
- The knob button is a separate pin and triggers calibration.

### Layout upload

- The firmware reports each key's `x / y / w / h` (0.25 u) so the host can draw the real layout
  and select keys by clicking it (`QUERY_LAYOUT = 0xFE`); the table is generated by `kle2c.py`
  and checked against `BUTTONCOUNT`.

### Firmware version check

- The device-info frame (`0xFF`) carries two versions, both packed as **2 | 3 | 3** bits:

  | Byte | Meaning |
  |---|---|
  | `[6]` | host version this firmware expects (currently `0x47` = 1.07) |
  | `[7]` | firmware version (currently `0x44` = 1.04) |

- The host compares them on connect and warns in the status bar, the log and the version label.
  It also keeps a "software version ↔ supported firmware range" table.

## Quick start

### 1. Flash the firmware

Open `Code/rtkb-layout-edited/rtkb-layout-edited.ino`, select **Arduino Leonardo**, upload.

### 2. Connect the host tool

1. Start [KeyboardOG](https://github.com/LGGZi/KeyBoard-OG-key-binding-tool), click "Refresh" and
   pick your keyboard (only devices that answer the device-info probe are listed).
2. Click "Connect": device info, mappings and hall parameters are read automatically.

### 3. Calibrate → tune → map

1. Calibrate once (hold the knob, or "Calibrate all" in the host).
2. Drag the RT / dead-zone sliders (values are per-mille of travel, `40` = 4%) and write them to
   the selected keys.
3. Finally write the key mappings; `CMD_REFRESH` follows automatically, no replug needed.

## Build from source

Dependencies: the bundled `EEPROM` / `HID` libraries — nothing extra.

Arduino IDE: open `Code/rtkb-layout-edited/rtkb-layout-edited.ino`, select **Arduino Leonardo**,
upload.

Command line (arduino-cli):

```bash
arduino-cli compile --fqbn arduino:avr:leonardo Code/rtkb-layout-edited
arduino-cli upload  --fqbn arduino:avr:leonardo -p COM5 Code/rtkb-layout-edited
```

Current footprint: ~11.8 KB flash of 28 KB, ~880 B RAM of 2.5 KB.

## Protocol at a glance

Commands and replies use **Report ID 4**, 8 bytes: `[0]` is the command code, `[7]` an
incrementing host sequence (the firmware drops a command identical to the previous one).

| Command | Value | Meaning |
|---|---|---|
| set mapping | 0x01 | `[1]=device [2]=key [3]=offset [4]=APPEND/OVERRIDE/CLEAR [5]=slot` |
| set parameter | 0x02 | `[1]=parameter [2]=key [3..4]=value` |
| calibrate | 0x03 | `[2]=ALL/SINGLE [3]=key` |
| query | 0x04 | `[1]=0 mapping / 1 parameter / 0xFE layout / 0xFF device info` |
| ACK / FIN | 0x05 / 0x06 | replies |
| refresh | 0x07 | reload from EEPROM |

Three things that bite most often:

1. **One command, two replies**: ACK then FIN; reading only one leaves the FIN for the next command.
2. **The device-info frame has no FIN**: end the query when the `0xFF` frame arrives.
3. **The firmware drops duplicate commands**: increment `[7]` every time.

Full byte layouts, reply formats and the EEPROM map are in
[`Code/rtkb-layout-edited/README.en.md`](Code/rtkb-layout-edited/README.en.md)
([中文](Code/rtkb-layout-edited/README.md)).

## FAQ

**Q: keys only work now and then, but the serial readings look fine**

- That is the classic "`buttonbuf` was a local variable" bug (the latch is lost). The current
  firmware keeps it `static`; use the matching firmware.

**Q: double click on light presses / sticky release**

- A double click usually means the dead zone is too large or `rt_active` too small; a sticky
  release points at `rt_deactive` or `low_deadzone`.
- Calibrate first, then tune: RT 10..500, dead zones 0..200.

**Q: one key is always pressed / its reading is odd**

- Check that key's analog channel, the magnet position, and the `_kbScan()` channel table.

**Q: the host reports a 3000 ms timeout right after connecting**

- The device-info frame has no FIN; end the query on the `0xFF` frame, and use a matching host
  version.
- Do not keep the Arduino serial monitor open (with `DEBUG` enabled the prints block).

**Q: can I change the key count?**

- Changing `BUTTONCOUNT` also touches: `key_map` dimensions, the EEPROM maths, the `_kbScan()`
  channel table and the layout table length.
